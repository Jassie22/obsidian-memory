# AI for Engineering — Cookbook

A short cookbook. Each entry = a situation you actually hit, and the tool that flattens it. Read end-to-end, or skim the headings and stop wherever sounds familiar.

You're taking **this repo** home. Clone it, run `./setup.sh`, and every Claude Code session on your machine picks up a vault, memory, `/recall`, and a set of hooks that keep it all in sync. That's entry #1 below. Everything after is what you do once that's in place.

---

## Quickstart (10 min)

```bash
git clone https://github.com/Jassie22/obsidian-memory ~/obsidian-memory
cd ~/obsidian-memory
./setup.sh --groups arc,personal
```

What that does:

1. Creates `~/vault/` with one folder per group.
2. Installs `claude-global/CLAUDE.md` → `~/.claude/CLAUDE.md` so every Claude session loads it.
3. Installs the hook scripts into `~/scripts/` (auto-pull, auto-commit, secret guard, proactive-note reminder).
4. Installs the semantic-search layer (`fastembed` + `sqlite-vec`) that powers `/recall`.

After that: open any repo, run `claude`, type `/resume`, and you've got a Claude that remembers.

Full setup details in the repo `README.md`.

## 1. Give Claude a brain that lasts longer than one session

**The problem:** every new chat starts from zero. You keep re-explaining what Charlie decided in the meeting, why you picked n8n over Netlify Functions, what the three agent prompts actually look like.

**The fix:** an Obsidian vault + hooks that Claude reads and writes to. Persistent. Semantic-searchable. Commits to git every time it changes.

Four commands you'll use every day:

- **`/recall <query>`** — semantic search over the vault. "What did we decide about the hero pill?" Claude reads the top 3 notes before answering. Beats grep. Beats memory. Beats Slack search.
- **`/capture <thought>`** — drop an idea into `inbox/` with no ceremony. Kebab-case filename auto-generated. Use it when you're half-way through something and don't want to break flow.
- **`/save`** — end-of-session log: what you did, what you decided, what's open, next step. Dropped into the right group folder. Wikilinked to every note you touched.
- **`/resume`** — start a new session with the last 3 logs + decisions already loaded.

And four things running in the background:

- **Proactive note-writer** — a hook injects a reminder every turn to capture durable context (decisions, gotchas, corrections). So Claude writes notes about your work *while* you're working, not just when you ask.
- **Auto-commit + auto-pull** — the vault syncs across your machines without you thinking about it. Every edit lands on origin within seconds.
- **Secret guard** — a `PreToolUse` hook blocks writes to `~/vault/` if a secret pattern is detected (`sk-...`, `ghp_...`, long hex blobs, `-----BEGIN PRIVATE KEY-----`). Plaintext memory stays safe.
- **Groups** — top-level categories (`arc`, `personal`, `research`). Keeps work and side projects from bleeding into each other. Edit `~/vault/.groups` to add your own.

**Graphify (optional, for code):** there's also a `graphify-out/graph.json` you can generate for any repo — a codebase knowledge graph Claude reads before diving into source. Install once, re-run on commit, navigate big repos without re-reading every file.

**Try it today:** clone the repo, run `./setup.sh --groups arc,personal`, open a Claude Code session in any project, type `/capture test — installed the memory system`. Check `~/vault/inbox/`. There's your first note.

## 2. Run it later / overnight

**The problem:** you want to kick off a long plan, but you're mid-day and you'll be in meetings. Or you're out of credits and would rather burn tomorrow's quota. Or you'd like a weekly "what changed in staging" summary without ever remembering to ask.

**The fix:** schedule Claude.

- **`/schedule`** — create, list, update, or one-shot-run a scheduled Claude agent. Cron-style. "Run this prompt every Monday at 9." "Run this once at 3pm." Works the same whether you're scheduling a simple summary or a full-blown multi-step plan.
- **`CronCreate`** (tool) — used under the hood. You can also drive it directly from inside a session.
- **`/loop`** — recurring execution in the *current* session. Good for "babysit this deploy for the next hour, check every 5 min."

**Example:** "Every Monday 08:00, read the last week of `arc/logs/`, write a one-paragraph team status, post it to Slack." Ten seconds to set up. Runs forever.

**When to use what:**
- A one-shot "do this at 3pm" → `/schedule` with a date.
- A recurring job → `/schedule` with a cron string.
- Polling inside an active session → `/loop`.

## 3. Claude Code, not a web chat

**The problem:** you paste a file into chat.ai, Claude suggests a change, you paste it back into your editor, you lose the surrounding context. Repeat 10 times. This is the 2× productivity ceiling.

**The fix:** Claude Code in your actual repo.

- Drop a `CLAUDE.md` at the repo root. Describe the repo's shape, the conventions, the gotchas. Every session in that directory auto-loads it.
- For sub-projects or clients, drop a `CLAUDE.md` in that sub-directory. Nearest-up wins.
- Use `/init` if you want Claude to draft the initial `CLAUDE.md` for you based on the repo.

**Rule of thumb:** if you're copy-pasting between an editor and a chat window more than twice in the same task, you're in the wrong tool.

## 4. Figma → code (Figma MCP)

**The problem:** translating a design to a component takes 20 minutes of eye-balling, and you still miss three tokens.

**The fix:** the Figma MCP server. Paste a Figma URL, Claude gets the actual node tree, design tokens, and a screenshot — then generates a scaffold that matches the design system.

Main tool: `get_design_context` — returns React + Tailwind by default, plus any Code Connect mappings if they're set up. Adapt to your stack from there.

**Two other useful ones:**
- `get_screenshot` — when you want Claude to "look at" a frame without the full node tree.
- `generate_diagram` — create a FigJam diagram from a description. Useful for sticking architecture sketches in front of designers.

**Setup:** install the Figma MCP in Claude Code (see link pack). Authenticate once. Then paste any `figma.com/design/...` URL into your prompt.

*Relevant to the Arc corp-site work Charlie's leading right now.*

## 5. GitHub-native PR work (GitHub MCP)

**The problem:** PR review means tab-switching between your editor and github.com, losing context each time.

**The fix:** the GitHub MCP server. Claude can read PRs, add comments, triage issues, check CI status — all without leaving the terminal.

Common patterns:
- `review this PR` → Claude reads the diff + description, posts line-level comments.
- `triage issues labelled 'bug'` → Claude reads them, proposes priorities and duplicates.
- `what's red on main right now` → checks CI.

Setup note: the hosted OAuth flow can be flaky. Easiest route is a Personal Access Token over HTTP — see the repo's `github-mcp-pat-workaround` note.

## 6. Subagents for parallel work

**The problem:** before you can make a change, you need to understand the codebase. That's half a day of reading. You can't usefully parallelise it in your head.

**The fix:** dispatch subagents. Multiple at once, running in parallel.

- **`Explore` agent** — fast, read-only, for "find all the places we do X." Use thoroughness: "quick" / "medium" / "very thorough."
- **`Plan` agent** — for "design me an approach to Y." Returns a step-by-step plan.
- **`general-purpose`** — open-ended research, wide searches, any multi-step task you'd otherwise do yourself.
- **`feature-dev:*`** — dedicated agents for architecture, exploration, and review inside a feature workflow.

**The trick:** dispatch multiple agents **in parallel** in a single message. Each one chews on its own slice. You get N results in the time of the slowest one. Works especially well for "I need to understand 3 different subsystems before I change any of them."

## 7. Skills for repetitive patterns

**The problem:** you find yourself telling Claude the same thing every time. "Write tests first. Match the existing conventions. Commit with a conventional prefix."

**The fix:** write a skill. Claude loads it on trigger and follows the instructions without you retyping them.

- Built-in skills already in use: `superpowers:brainstorming` (scopes features before code), `superpowers:test-driven-development` (TDD flow), `superpowers:systematic-debugging` (for any bug), `simplify` (review + refactor changed code), `claude-md-management:*` (CLAUDE.md maintenance).
- **Write your own** with `skill-creator`. One skill per repeated workflow. Example: a "ship-feature" skill that runs brainstorm → spec → TDD → commit → PR in sequence.

**Start simple:** pick the three sentences you retype most often to Claude. That's your first skill.

---

## 8. Cursor for inline fixes

**The problem:** full Claude Code sessions have overhead. Sometimes you just want to fix the one typo or rename the one variable, in-editor.

**The fix:** Cursor (or Zed, or Copilot) stays in your editor. Positioned as a **companion, not a replacement** for Claude Code.

Rule of thumb:
- **Claude Code** when the task spans >1 file, needs long context, or you want the memory/skills layer.
- **Cursor** when the edit is visible on screen and the change is <10 lines.

No setup to teach here — it's a separate install with its own docs.
